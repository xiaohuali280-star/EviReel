## 运行中发现并修复的问题

### 第一轮：真实服务对接（10-31）

| 现象 | 原因 | 修复 | 回归测试 |
| --- | --- | --- | --- |
| 画面索引失败：图像 Embedding 返回 HTTP 400（code 20015） | SiliconFlow 的多模态 Embedding 要求 `{"image": <URL 或 data URI>}`，客户端发送的是对话接口风格的 `content` 数组 | SiliconFlow 使用 `{"image": ...}`，其他供应商保持原格式 | `test_siliconflow_image_embeddings_use_the_image_input_format` |
| 文稿可读但不可检索：`transcript_embedding_failed` | 供应商把一次请求按 8 条拆成子批，每批从 0 编号（20 条输入返回 0..7、0..7、0..3），严格编号检查把合法结果判为错误；异常被吞掉没有日志 | 接受“等长子批、按输入顺序、每批从 0 编号”的格式，其余重复或缺失编号仍报错；转写索引记录失败原因 | `test_embedding_sub_batches_numbered_from_zero_keep_input_order` |
| 笔记生成失败：`study_invalid_output`（`JSONDecodeError`） | 模型把 JSON 包在 Markdown 代码块里；问答路径会去掉代码块，笔记路径没有 | 笔记解析同样去掉外层代码块 | `test_fenced_json_from_the_model_is_accepted` |

### 第二轮：回答里的误导性文字（11-01）

10-31 的截图里，三条真实回答都以“部分画面未能核实”开头，两条还带“语音与画面证据存在冲突”，正文末尾有 “(118.00–118.00s)” 这样的原始秒数。逐条核对后：

| 现象 | 原因 | 修复 | 回归测试 |
| --- | --- | --- | --- |
| 每条回答都以“部分画面未能核实”开头 | 只要请求中出现 `related_frames_unavailable`（某段字幕附近 ±2 秒没有帧；幻灯片视频只在 0 / 70 / 118 秒有帧）就加前缀，而实际上画面检查执行了，回答引用的画面也读过 | 前缀只在回答引用的画面类证据（帧 / 事件 / 摘要）没被读到，或画面问题没有读到任何被引用的证据时添加 | `test_the_unverified_frames_prefix_follows_the_cited_evidence_not_any_warning` |
| “语音与画面证据存在冲突” | 视觉核验把本次检索到的**全部**字幕都和当前帧比较，例如拿 75 秒讲并查集的语音去对 118 秒的复杂度幻灯片，于是报“不一致”；同时把 “e-log e” 这类误识别也当成内容冲突 | 只把这些帧在屏幕上时说的话交给视觉核验（帧时间 ±`RETRIEVAL_NEIGHBOR_S`）；核验与回答提示词区分“识别错误”（`possible_asr_error`）和“内容真正矛盾”（`speech_visual_conflict`） | `test_the_frame_check_only_compares_speech_said_while_those_frames_were_shown` |
| 正文末尾的原始秒数 “(118.00–118.00s)” | 后端在每条结论后追加证据编号和秒数，前端只去掉了编号 | 前端显示时去掉整个引用标记，时间由下方来源卡片以 mm:ss 显示；API 返回的文本格式不变 | 前端 `answerText` 单元测试 |

重问三个问题后：三条回答都不再有“部分画面未能核实”和“冲突”；第一、三题标注“字幕可能存在识别错误”（对应字幕确有 “复杰点”“e-log e”），第二题直接回答 Gradescope。
