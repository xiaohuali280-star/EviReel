# 文稿自然段阅读与逐句模式任务计划

日期：2026-10-24（Asia/Shanghai）。

执行授权：用户已于 2026-10-25 确认按本计划实施、验证并上传 GitHub，直接修改默认 `main`，不创建分支或 PR。实施与真实视频验收已完成，回归和上传状态见 [交付记录](TRANSCRIPT_READING_DELIVERY.md)。

## 1. 目标与现状

采用已选方向：**自然段合并阅读 + 随视频长度调整段落密度 + 可切回逐句模式**。

- 文稿默认以连续自然段展示，减少每几秒一个时间戳造成的碎片感；全文保留，不生成摘要、不删口头语、不改写专业术语。
- 保留原始识别片段及其时间范围，用于逐句查看、播放定位、字幕导出和证据引用。
- 短视频使用较细的阅读粒度，长视频适度合并；最终分段同时考虑完整句子、停顿和文字量。
- 已有视频在读取原文后即可使用，不要求重新识别、不调用外部模型、不新增密钥。

代码核对结果：

- `frontend/src/App.tsx` 当前调用 `transcripts?kind=segments&limit=100`，每个原始片段单独呈现。
- `vam/asr/worker.py` 保存识别引擎提供的时间区间，并非统一固定为 5 秒。
- `vam/asr/chunker.py` 的 `make_chunks` 服务现有文本分块，遇到句末标点即结束当前块，不能直接等同于多句合并的阅读段落。
- 本次新增展示层分段，不修改原始片段、后端检索块或转写版本，不触发索引重建。

## 2. 页面与交互

### 2.1 入口

- 继续使用播放器下方现有“文稿”入口及收起/展开行为，首次进入视频时学习区仍默认收起。
- 展开文稿后，工具栏提供“段落阅读 / 逐句模式”两项互斥选择，默认段落阅读。
- 保留“语音识别文稿 · 未经人工校对”、TXT、SRT、重试处理及现有状态提示。
- 段落阅读显示简短说明：“按句子与停顿自动合并，原文完整保留”。逐句模式说明其显示原始识别片段；“逐句”不承诺每条恰好是一句完整语法句。

### 2.2 阅读与定位

- 段落阅读：每段显示起止时间与合并正文；点击段落跳到首个来源片段的开始时间，不推算词级时间。
- 逐句模式：沿用每个原始片段的时间、正文与点击定位，便于精细核对。
- 播放时，根据当前时间是否位于某个真实来源片段内高亮对应段落或片段；不把段落中间的静音空隙标成正在说话。
- 切换模式时保持播放器时间、播放状态和输入草稿。以当前可见条目对应的来源片段为阅读锚点，切换后定位到含该片段的条目；没有可见锚点时使用已加载范围内的播放位置，再回退到开头。
- 模式切换仅调整文稿容器滚动，不主动播放视频，不抢走键盘焦点，不因播放进度持续强制滚动。
- 学习区收起再展开保留模式、已加载内容和阅读位置；切视频清空原视频的文稿与锚点。

### 2.3 偏好与兼容

- 将阅读模式作为浏览器偏好保存，首次默认段落阅读；刷新和切视频沿用该偏好。存储失败或值无效时安全回退。
- 仅保存模式名称，不将文稿正文写入浏览器持久存储。
- 控件支持键盘操作、明确的选中状态与读屏名称；兼容深浅主题、手机、左侧最小化和两栏宽度拖动。

## 3. 自适应分段规则

### 3.1 时间粒度

以视频有效时长 D（秒）计算期望段落时长：

`T = clamp(round(22 × sqrt(D / 480)), 12, 45)` 秒。

这是展示目标，不是固定切割窗口或强制段落数量。时长缺失、非正数或非有限数时使用 22 秒，待有效时长可用再重算并保留来源锚点。

| 视频时长 | 期望段落时长 T | 说明 |
| --- | --- | --- |
| 2 分钟 | 12 秒 | 保留短视频的阅读粒度 |
| 8 分钟 | 22 秒 | 连续语音理想情况下约 22 段，实际受停顿、字数和原始片段影响 |
| 30 分钟 | 43 秒 | 降低长视频条目密度，同时受字数上限约束 |
| 60 分钟 | 45 秒 | 达到时间粒度上限，不随总时长无限放大 |

连续公式避免相差几秒的视频因跨档位突然改变密度。视频总时长包含静音，必须由停顿和字数约束修正，不能仅按 D/T 决定实际段数。

### 3.2 句子、停顿和长度

按接口提供的来源片段顺序处理，使用以下优先级：

1. 原始片段是最小时间单位。保留其 ID、顺序、文字和时间，不将一个片段拆开再均分时间。
2. 相邻来源片段之间的静音间隔达到 2 秒时结束前一段，避免跨明显停顿合并；重叠片段不视为静音。
3. 当前段达到 T 秒或约 180 字符后，优先在来源片段的句末标点处结束。识别中英文句末标点，并处理末尾引号、括号；分号不单独作为必须结束段落的条件。
4. 缺少标点时继续寻找边界，但设 320 字符及 `min(2 × T, 90)` 秒的合并上限。加入下一片段会越界时，在原始片段边界换段，不截断片段正文。
5. 单个原始片段已超出上限时独立呈现，允许该段超限；不伪造更精确的时间，不丢弃文字。
6. 视频结束时输出剩余段落；不为凑目标段数合并跨停顿内容。

上述字符预算按 Unicode 码点计数，作为中英文通用的版面约束，不等同于词数。首轮真实阅读验收可调整参数，但必须记录原因并通过同一批边界用例。

### 3.3 内容与来源不变量

- 纯展示函数输出段落起止时间、合并文字及有序来源片段映射；段落时间为来源片段起止时间的外包范围，实际高亮使用来源区间。
- 每个输入片段恰好归属于一个输出段落；文本、标点和来源顺序不得丢失、重复或改写。
- 拼接只增加必要的阅读空白：中文句子之间避免机械插入多余空格，英文词句之间保留必要间隔；原片段内部文字不修改。
- 段落 ID 由文稿版本和首个来源 ID 组成，避免加载更多时因数组索引变化造成整列表重建。
- TXT/SRT 继续使用现有原文导出，聊天引用与检索继续使用既有来源 ID。本次不增加段落导出、AI 整理或章节折叠。

## 4. 数据加载与状态边界

- 两种模式共用原始片段缓存和现有分页接口，模式切换不重复发起识别或全量读取。
- 保留首次展开才加载和每批 100 条的机制，不为计算所有段落一次拉取整段长视频文稿。
- 分页边界不作为自然段边界：最后一段可继续接收下一页片段，已完成段落保持稳定；增量处理与同版本完整输入分段应一致。
- 尚未全部读取时明确显示“已加载 X/Y 条原始片段”，不把当前段落数量冒充全文数量。加载更多可延续最后一段，并保持可见来源锚点。
- 防止重复加载；失败保留已加载内容并允许重试，不重复追加片段。模式切换无需重新请求同一批数据。
- 切视频或重试产生文稿新版本时，隔离旧请求和旧缓存。分页响应版本不一致时重新从第一页加载，不混合版本。
- 在途请求使用视频、版本和请求代次校验；旧请求返回或结束时不能覆盖新视频内容及其加载状态。
- 处理空文稿、未就绪、识别失败、播放不可用及只有一个片段等状态；维持现有功能提示和恢复入口。

## 6. 验证与验收标准

### 6.1 分段规则与数据完整性

- 验证短、中、长视频、无效时长、时间粒度上下限，以及标点缺失、中英文混合、末尾引号、明显停顿、重叠时间和单片段超限。
- 验证每个来源片段只出现一次、顺序不变、原文可完整还原、所有输出时间均来自原始片段。
- 使用跨第 100/101 条及多个分页边界的样本，确认分页合并结果与完整输入一致，尾段连续且没有遗漏或重复。
- 用约 8 分钟、154 个短片段的连续语音夹具验证明显减少条目；该夹具目标约 20～30 段。真实视频因停顿和文字密度可超出范围，不以凑数牺牲分段合理性。
- 对原有最大规模限制内的长文稿检查增量处理和交互响应，不在每次播放时间更新时重新分组全文。

### 6.2 浏览器交互

- 默认段落阅读；切回逐句模式可看到全部已加载原始记录，来回切换不触发重复识别、不丢正文。
- 点击段落和逐句条目定位正确；静音间隙无错误高亮；模式切换保留播放状态和可见阅读锚点。
- 覆盖加载更多、失败重试、重复点击、模式快速切换、切视频时请求晚返回及文稿版本更新。
- 覆盖学习区收起/展开、聊天资源卡打开文稿、刷新后的偏好恢复及浏览器存储不可用。
- 检查手机、深色模式、键盘操作、侧栏最小化与两栏拖动；不产生整页横向滚动。
- 抽查 TXT/SRT 下载及聊天引用定位，确保与原始识别片段一致。
