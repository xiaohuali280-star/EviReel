# 右侧聊天与八个快捷入口设计方案

日期：2026-10-23
状态：用户已审核并授权实施，A–F 的实现及本地真实验收已完成；正在上传 `main` 并核对 GitHub CI。交付证据见 [实施报告](CHAT_ACTIONS_DELIVERY.md)。

## 1. 目标与当前问题

目标：右侧支持真实视频问答；四个功能卡片和四个推荐问题都能一键生成用户消息、自动发送、显示处理状态，并在聊天区返回回答或任务结果。

实施前核对的问题（以下为原始问题记录）：

- `frontend/src/App.tsx` 的 `ready` 要求画面索引或语义检索索引可用，可读文稿本身不能启用聊天。
- `vam/indexing/service.py` 的 `retrieval_context()` 同样拒绝没有这两类索引的请求。因此，只取消前端禁用不能解决问题。
- 四个推荐问题调用 `setDraft()`，只填入输入框；四个功能卡片分别跳转、填问题或调用学习任务，行为不一致。
- 欢迎区进入对话后消失，后续只保留两个推荐问题，四个功能无法持续使用。
- 现有聊天已有会话持久化、请求幂等、断线恢复和跨视频隔离，应继续复用。

## 2. 用户交互

### 2.1 统一的一键发送

八个入口均采用：**点击 → 生成明确的用户消息 → 自动发送一次 → 聊天区显示用户气泡和处理状态 → 展示回答或任务卡片**。无需再次点击发送。

快捷入口生成的消息直接进入聊天记录。手动输入框继续支持输入、Enter 发送、Shift+Enter 换行。

- 未建立会话：先建立当前视频的会话，再自动发送同一请求。
- 连续点击：立即锁定当前发送入口，避免 React 状态更新前重复创建会话或任务。
- 输入框已有草稿：快捷入口使用独立消息，保留原草稿，避免覆盖用户文字。
- 同一会话回答期间：八个入口暂时禁用并显示忙碌原因；普通问题发送失败后保留消息并提供重试。
- 连接恢复：沿用原请求 ID 查询/重放，避免同一动作重复生成或重复计费。
- 切换视频：未发送的快捷请求取消，已接收任务继续在原视频后台运行；结果只回到所属会话。

### 2.2 四个功能卡片

| 功能 | 自动发送的消息 | 真实处理与聊天结果 |
| --- | --- | --- |
| 自动生成笔记 | 请根据当前视频生成完整的章节与学习笔记，覆盖主要内容，并提供来源时间定位。 | 复用当前有效笔记；没有时启动现有学习任务。聊天显示生成状态、章节摘要，以及查看笔记/下载 Markdown 按钮。重新生成使用明确的独立按钮。 |
| AI 看视频 | 请帮我理解当前视频的主要内容、核心观点和关键时间点；结合当前可用的画面与文稿，并说明依据。 | 执行真实视频问答。画面可用时参考画面；只有文稿时显示“基于语音文稿”，明确画面分析尚未就绪。返回内容概览和来源定位。 |
| 生成文稿 | 请提取当前视频的完整语音文稿，保留时间标记，并提供 TXT 和 SRT 下载。 | 已有文稿直接提供分页预览和下载；尚无文稿则复用/启动语音任务。识别不到语音时如实说明。不会以模型改写内容替代识别原文。 |
| 生成课件 | 请根据当前视频整理学习课件，包含章节标题、核心知识点和来源时间，并提供 PPTX 和 PDF 下载。 | 基于当前有效笔记导出真实课件；缺少笔记时先运行学习任务。聊天显示准备状态及 PPTX/PDF 下载按钮，课件继续使用现有文本型学习课件能力。 |

四个卡片保留现有名称、颜色及图标。任务结果同时同步到左侧学习区；用户可以始终从聊天区完成查看或下载。

### 2.3 四个推荐问题

| 展示文字 | 自动发送内容与范围 |
| --- | --- |
| 这段视频的主要内容是什么？ | 发送原问题，范围为当前整段视频。 |
| 帮我总结这节课的重点 | 发送原问题，范围为当前整段视频。 |
| 这部分的要点有什么好处？ | 优先附带明确选中的章节及其真实时间范围；没有选中章节时使用播放器当前时刻所在的文稿范围；没有可用局部范围则先澄清。聊天中显示具体章节/时间，不发送含糊的“这部分”而让模型猜测。 |
| 有哪些值得记录的知识点？ | 发送原问题，默认范围为当前整段视频。 |

为“明确选中章节”记录独立状态，不能把页面默认展示的第一个章节当作用户主动选择。所有时间和章节范围由服务器校验，模型不能自行生成定位数据。

## 3. 聊天可用性与回答依据

由服务器给出当前视频的聊天能力，前端据此显示状态和按钮，避免前后端判断不同。

| 可用材料 | 聊天方式与页面提示 |
| --- | --- |
| 画面索引/语义索引可用 | 使用现有带来源检索的问答流程。 |
| 索引不可用，但有可读文稿或仍有效、可验证来源的笔记 | 使用文本问答路径，显示“基于语音文稿/学习笔记”，不因 Embedding 失败禁用聊天。 |
| 仅有视频文件，内容尚未准备好 | 显示真实处理原因。普通内容问答等待材料就绪；可用的语音处理入口单独开放，已有同类任务则显示进度。 |
| 无视频、视频在回收站或已删除 | 显示上传/恢复提示，内容问答不可发送。 |
| 缺少模型配置或服务调用失败 | 显示可操作的原因。已存在的笔记、文稿和课件下载仍可使用。 |

文本路径设计：

1. 从当前视频读取并固定文稿 `text_version`，必要时读取同版本有效笔记及其证据快照。
2. 局部问答按章节范围或本地文本匹配选择材料，不强制调用 Embedding。匹配数量、上下文长度和模型输出均有上限。
3. 整片概览优先使用已完成的完整笔记；缺少完整笔记且全文超出上下文预算时，使用已有完整分批学习任务，不只取前几段并声称总结了全片。
4. 模型依据提供的材料回答；不足时说明不足，回答附真实文稿片段、章节及时间来源。语音文稿不含的画面内容不作臆测。
5. 文稿证据按 `text_version` 校验，检索证据按对应版本校验；同步修正服务端历史消息标记与前端来源卡片，避免无语义索引时所有文本引用被误标为失效。
6. 模型传输采用已验证的流式、有界超时和错误分类。重用可靠的请求实现或提取公共部分，避免复制另一套不一致的重试逻辑。

## 4. 聊天区布局与状态

- 无消息时保留当前欢迎布局：四个功能卡片、四个推荐问题和输入框。
- 第一条消息发送后进入对话视图。对话区顶部保留可展开的“快捷功能”区，仍能访问全部八个入口；新对话恢复欢迎布局。
- 发送后自动滚动到新消息；用户向上阅读历史时不强制跳到底部，提供“回到最新”。
- 回答显示处理阶段；能够稳定接收增量正文时展示逐步生成内容，最终回答成功保存后标记完成。
- 笔记、文稿、课件使用任务卡片显示“准备中/生成中/已完成/失败”，完成卡片包含摘要、查看入口和真实下载按钮。
- 生成任务与聊天请求分开记录：收到“任务已创建”不等于生成完成。卡片关联持久任务，刷新或断线后查询任务结果；后台生成不占用整个聊天连接等待。
- 长文稿使用分页预览，完整内容通过 TXT/SRT 下载，不一次性塞满消息列表。
- 模型鉴权、限流、连接、超时、材料不足等错误就地展示，失败保留旧成品和草稿。

## 5. 接口和代码变更范围

| 层面 | 计划改动 |
| --- | --- |
| 视频能力接口 | 在当前视频详情中增加聊天模式、不可用原因和各快捷动作可用状态；复用已有接口路径。 |
| 消息协议 | 兼容现有 `type=text`；增加可选、严格枚举的 `action` 和经校验的章节/时间上下文。普通聊天不带动作，四个推荐问题沿用普通文本问答。后端按明确动作执行，不只让模型猜测点击了哪个卡片。 |
| 前端发送 | 新增统一的快捷动作配置和发送入口，统一创建会话、即时发送锁、消息回显、请求 ID 和错误恢复。 |
| 后端对话 | 在持久会话流程内分发普通问答和四种动作；增加文本材料路径，保留已有检索路径。 |
| 后台任务 | 笔记/语音任务继续调用现有服务；按视频、动作和来源版本复用在途任务，完成后引用成品。聊天断线或任务卡片收起不取消生成。 |
| 消息结果 | 增加可选任务/成品资源引用；只保存经服务器验证的 ID。下载 URL 由服务器构造，校验视频归属与版本，不接受模型返回的任意下载链接。 |
| 引用与版本 | 更新文本引用的当前版本判断。旧文稿的下载入口必须匹配文稿版本或明确标旧，避免用旧消息入口静默下载另一版文稿。 |
| 持久化 | 优先复用当前请求 payload、结果 JSON 和任务表；只有确需新增字段时才加入可重复执行的迁移，不破坏历史对话。 |
| 构建与文档 | 同步前端类型、生产资源、协议说明、操作说明和交付验证报告。 |

主要涉及 `frontend/src/App.tsx`、`chat.ts`、`types.ts`、`style.css`、`vam/protocol.py`、`conversation_service.py`、会话/索引接口、文本证据读取及现有学习服务；新增模块按问答材料和快捷动作职责拆分。

## 6. 实施顺序

| 步骤 | 任务 | 完成标准 |
| --- | --- | --- |
| A | 补充当前禁用及八入口行为的回归用例；定义能力、动作、资源引用协议 | 测试能复现“已有文稿但不能聊天”和“点击只填草稿”的问题。 |
| B | 实现文本问答及能力判断，修正文本引用版本检查 | 索引不可用但文稿可读时，普通问题能得到有真实来源的回答。 |
| C | 统一八入口的一键发送与会话创建 | 每次点击立即显示一条正确的用户消息，自动发送，连续点击不产生重复请求。 |
| D | 接入四个真实功能及任务卡片 | 能在聊天区获得笔记、文稿、视频解读和课件结果，并下载真实文件。 |
| E | 完善持续可见的快捷入口、重试、断线恢复与跨视频隔离 | 刷新、切换视频和临时断网不会丢任务、串消息或重复生成。 |
| F | 完整回归、真实模型验收、更新构建与交付说明 | 所有验收项通过；检查提交范围与密钥后直接上传 `main`，核对 GitHub CI。 |

## 8. 审核重点

建议采用本方案的“点击立即自动发送”：四个功能同时执行真实任务、在聊天中反馈结果；四个推荐问题直接发送。先解决文稿问答可用性，再统一入口，最后验收与上传。

方案已审核，业务实现与验收结果记录在 [实施报告](CHAT_ACTIONS_DELIVERY.md)。真实接口测试只使用本次视频已有文稿和用户授权的测试上下文；原始视频、文稿、密钥及运行日志不进入提交。
