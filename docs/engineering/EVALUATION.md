# EviReel 评测：方法、结果与缺口

**真实评测未做。** 本文的结果全部来自**合成题集 + 确定性模拟器**。它们证明评测工具、指标、版本固定、路由规则和用量记账能正确工作，并让路由规则改过一次；**不能当作真实回答质量、真实延迟或真实成本**。真实评测的补齐步骤见第 6 节。

## 1. 题集与语料

| 项目 | 内容 |
| --- | --- |
| 题集 | `eval/synthetic/questions.jsonl`，32 题，sha256 前缀 `d85dd257f346` |
| 标签来源 | 全部 `synthetic`：由我按合成语料编写，每条参考时间段都与语料文本核对过（`python -m vam.evaluation check` 自动校验），**不是人工金标准** |
| 划分 | 调参集 17 题 / 保留集 15 题；只在调参集上选阈值，保留集单独报告 |
| 类别 | 字幕可答 11、需看画面 8、跨片段 4、无答案 5、连续追问 4；标记：中文术语 5、代码符号 10 |
| 语料 | `eval/synthetic/fixture.json`（sha256 前缀 `8964ef7d79ef`），两门为评测编写的合成课程（中文算法课 480 s、Python 代码课 360 s），按索引器的表结构写入真实的帧库和字幕库。部分事实只出现在画面标题里，用来考察“需看画面”的题 |
| 模型 | 模拟器（`vam/evaluation/simulator.py`）：词袋哈希“向量”、重叠度“重排”、读取帧标题的“VLM”、按词重叠引用证据的“LLM”。所有调用都经过 ModelGateway，带固定的模拟延迟（Embedding 40 ms、重排 150 ms、VLM 800 ms、LLM 400 ms） |

模拟器按词重叠打分，天然偏向关键词通道，也不会理解语义。所以“哪个配置更好”在模拟器上只说明规则在按设计工作，真实模型上可能完全不同。

## 2. 指标定义与分母

定义写在 `vam/evaluation/metrics.py`，这里是摘要：

| 指标 | 定义 | 分母 | 无法计算时 |
| --- | --- | --- | --- |
| 证据 Recall@K | 前 K 条证据中，与参考时间段重叠（两端各放宽 2 s）且来源匹配的参考数 / 参考数，再对题取平均 | 可答题 | — |
| Hit@K、MRR | 前 K 条是否命中任一参考；第一条命中证据的倒数排名 | 可答题 | — |
| 引用支持率（自动） | 引用的时间段与参考匹配的比例。**只检查引用指向哪里，不检查文本是否支持结论** | 可答题上的全部引用 | 没有引用时为 `—` |
| 引用支持率（人工） | 需要人工复核 | — | 本次未复核，记为未做 |
| 时间定位误差 | 第一条引用（没有引用时取第一条证据）的起点与最近参考起点之差，单位秒；报中位数 | 可答题 | 没有证据时不计 |
| 无答案拒答率 | status 为 refused 或 uncertain 的比例 | 无答案题 | — |
| 误弃答率 | 可答题被 refused 或 uncertain 的比例 | 可答题 | — |
| 关键词代理 | answered 的回答包含全部 `answer_keywords`。很弱的自动代理，只作参考 | 已回答的可答题 | — |
| 延迟 | 每题检索加回答的墙钟时间（模拟延迟 + 真实检索计算），P50 / P95 | 全部题 | — |
| 调用数、token | 每题经过 ModelGateway 的模型尝试数和 token（模拟器按字符估算） | 全部题 | — |
| 单题费用 | 按 `MODEL_PRICES` 计算 | 全部题 | 未配置价格时为 `—`，报 token 代替（本次即如此） |
| 通道失败 | 被限流、超时等原因跳过的通道次数；非零说明结果不完整 | — | — |

每个目录都有：每题一行的原始结果（`*.results.jsonl`）、`metadata.json`（代码版本、环境、题集与语料哈希、配置、模型身份、阈值）、`summary.json`（总体、按划分、按类别、按标记）、`comparison*.md`。模拟器是确定性的，两遍之间只有延迟不同。

复现命令：

```bash
python -m vam.evaluation run --dataset eval/synthetic/questions.jsonl --fixture eval/synthetic/fixture.json \
    --models simulator --configs all --repeat 2 --set route_min_similarity=0.2 --out <目录>
```

开发中发现并修正的工具问题（发生在任何结论之前）：

- 用量记录按题目编号归属，导致各配置的调用数互相累加。已改为按（配置, 轮次, 题目）归属。
- 第一条查询冷启动拉高了 P95。已加预热查询。
- 默认限流（每空间每分钟 120 次）让模拟器的部分通道被限流，导致结果依赖时机，例如阈值不同时召回也不同。模拟器运行改为关闭限流；真实运行保留限流，并在汇总里报告通道失败次数。

## 5. 读法与据此做的改动

在模拟器上能说的：

1. **规则路由按设计工作，并因评测改过一次。**
   - 第一版规则（`sim-all-v1`）把“事件摘要或帧相似度高”当作视觉题足够，结果 `auto` 在需看画面的题上 100% 误弃答，与 `deep` 的 38% 相差很大。
   - 修订为“视觉题必须看过帧才算足够”，并加上“低成本回答被模型标为证据不足时升级一次”。之后 `auto` 的误弃答率与 `deep` 持平（全量 19%，保留集 15%），token 少约 1/3，P50 约减半；字幕可答题走低成本路径。
   - 这说明的是规则把题分到了预期的路径上；真实模型上的取舍要重新测。
2. **阈值的取舍**：调参集上，`route_min_similarity` 从 0.5 降到 0.2，误弃答从 64% 降到 21%（v2，`auto`），token 约增加到 2.2 倍。0.2 只是在模拟器上选的值；真实 Embedding 的相似度尺度不同，必须在真实调参集上重选。
3. **关键词通道有利有弊**：
   - 在模拟器上，中文术语和代码符号的首位命中明显提高；
   - 但需看画面的题 Recall@5 从 75% 降到 38%，因为字幕命中挤掉了帧证据；
   - 由于模拟器本身按词重叠打分，这里的提升不能外推；
   - 默认继续关闭，等真实评测决定。
4. **多通道融合时首位常是画面或事件证据**，字幕可答题的 Recall@1 低于只用字幕（19% 比 56%），Recall@5 更高（85% 比 70%）。是否要按问题类型调整通道优先级，需要真实数据。
5. **追问**：用“历史问题 + 当前问题”拼接代替产品里的 LLM 改写（标为模拟），低成本路径误弃答 50%，看画面后为 0%。真实效果取决于产品的改写模型。

不能说的：任何“准确率提升 X%”“成本降低 X 元”。

## 6. 真实评测的缺口与最短补齐步骤

缺：有授权的视频；人工标注；模型预算（另外重排序 key 为空）。补齐步骤：

1. 准备 3–5 个有授权的课程视频，导入平台并完成索引。
2. 人工标注 30–50 题（格式同合成题集，`label.source=human`，写明在视频上核对的时间段），分调参集和保留集，覆盖五个类别和中文术语、代码符号两个标记。
3. 确认预算后运行（调用次数和 token 上限由账本强制执行）：
   ```bash
   python -m vam.evaluation run --models real --data-root <DATA_ROOT> --dataset <题集> \
       --allow-paid --max-calls <上限> --max-tokens <上限> --configs all --repeat 2 --out <目录>
   ```
   配置 `MODEL_PRICES` 才会计算费用。
4. 在调参集上重选 `route_min_similarity` 和 `route_min_keyword_coverage`，在保留集上报告。
5. 人工复核引用是否支持结论（单列一栏，不与自动指标混合）。
6. 据此决定是否默认开启关键词通道和 `auto`。没有改善的配置如实记录、保持关闭。

多轮 Agent 的评测入口未实现（需要真实的工具调用模型），列为未做。
