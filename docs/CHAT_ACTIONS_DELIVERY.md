# 聊天与八个快捷入口交付记录

日期：2026-10-23（Asia/Shanghai）。按用户审核通过的 [方案](CHAT_ACTIONS_PLAN.md) 实施，直接在 `main` 开发。

## 已实现

- 四个功能卡片和四个推荐问题均立即生成一条用户消息并自动发送。首次点击会先创建会话；同步发送锁防止连续点击重复创建。快捷消息保留输入框草稿，对话开始后可展开“快捷功能”继续使用八入口。
- 普通聊天复用持久会话、请求 ID、断线重放和 HTTP 状态恢复。切换视频隔离迟到结果；重试保留动作、范围。原有会话和请求无需数据库迁移。
- 可读文稿启用文本问答，不再要求语义索引成功。答案标明“基于语音文稿 · 未分析画面”，附可核对的真实来源；画面/语义索引可用时继续使用原检索流程。
- “这部分”优先绑定用户主动选择的章节，否则使用播放位置范围，并校验真实时长和当前来源版本；没有范围时请求澄清。
- 笔记、文稿、课件使用真实后台任务和持久资源卡。已有有效成品直接复用；生成中显示进度，刷新后恢复。笔记每次预览 5 章、文稿 10 段，可加载更多；完整资料通过真实下载获取。
- Markdown、TXT、SRT、PPTX、PDF 下载地址由服务器生成，校验视频归属。旧笔记保留成品并标旧，旧文稿链接拒绝下载新版，过时来源不能直接定位。
- 模型鉴权、限流、连接、超时、缺少材料、输出校验失败均给出中文提示；后台任务确认与真正完成分开显示。阅读旧消息时不强制滚到底部。

## 真实验收发现与修复

用户明确授权将已有文稿及测试对话发往配置的 `api.siliconflow.cn`。使用本地实际视频、已有 18 个文稿片段和有效 5 章笔记验收；未新增原始视频画面上传，未修改系统代理或服务商设置。

1. 文稿可读但语义检索失败导致聊天禁用：新增独立文本路径和统一能力返回。
2. 原严格检索规则把课程学习时长也当成播放定位拦截：只在文本路径允许材料中的自然语言时长事实，时钟定位、URL 和伪造来源仍被拒绝，默认检索策略不变。
3. 历史回答的长来源 ID 干扰本轮引用：历史只用于理解问题，去掉旧引用身份；本次用短来源别名，再映射到服务器真实记录。
4. 配置模型会输出重复 JSON，或将 claims 与 warnings 拆成相邻对象：仅兼容完全相同的重复答案、互不冲突的两个固定字段对象；消费完整响应，不丢弃尾随正文，不在冲突答案中任意选择。之后仍进行严格结构和当前来源校验，最多一次重新生成。冲突、未知字段、伪造来源和无效定位继续失败，不向用户发布未校验答案。
5. 聊天请求持有视频删除租约时，文稿入口原本不能启动语音任务：增加仅内部使用的调度选项，保留写入锁和原公共接口的忙碌保护；回归验证实际完成语音任务并释放租约。

## 本地使用

已运行开发服务：前端 `http://127.0.0.1:5173/`，后端 `http://127.0.0.1:8000/`。刷新页面选择视频，即可点击功能卡或推荐问题；已有会话从“快捷功能”展开。各资源卡在后台任务完成后开放查看与下载。
